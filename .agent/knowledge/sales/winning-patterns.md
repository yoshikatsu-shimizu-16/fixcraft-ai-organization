# Winning Patterns

勝ち筋は案件ごとのEvidenceから作る。基本原則は、課題を具体化し、最初の小さな成果物または検証方法を提示し、顧客の技術・納期・品質リスクを下げること。

WordPressでは復旧・安全性・ロールバック、GAS/自動化では再実行性・権限・失敗通知、HP/LPでは顧客理解・情報設計・実在感、一般開発では受入条件・変更境界・テストを先に示す。

価格競争は最後の手段とし、「なぜこの人なら事故らず早く終わるか」を具体的に説明できる提案を優先する。Prototypeは受注前に完成品を無料提供するためではなく、最大の不安を小さなProofで除くために使う。
