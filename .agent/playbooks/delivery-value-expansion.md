# 納品前の価値確認と追加提案

## 目的

納品前に、依頼された作業を安全に完了させたうえで、顧客が次に困りそうな点をEvidenceに基づいて確認する。改善案、顧客にとっての効果、追加費用・納期を一緒に示し、単発納品から次の相談につなげる。

本Playbookは既存契約のScopeを広げる指示ではない。追加作業は別提案として扱い、顧客の明示承認とプラットフォーム上の契約・規約に沿った手続きが済むまで着手しない。

## 適用タイミング

- 納品直前の最終確認
- 顧客に成果物を見せるとき
- 検収後の完了連絡
- 顧客が追加要望や不安を伝えたとき

## 手順

1. **契約Scopeを再確認する。** 依頼内容、受入条件、除外事項を見直し、契約内作業と追加候補を分ける。契約内の未完了項目を追加料金の提案にすり替えない。
2. **顧客視点で確認する。** 納品物を実際の利用状況に近い条件で点検する。Web制作ならスマートフォン表示、主要導線、問い合わせボタンの押しやすさを含む。自動化なら再実行、権限、失敗時の通知など、その成果物の用途に応じた項目を確認する。
3. **追加改善候補を絞る。** 顧客が実際に困る根拠があるものだけ選ぶ。見つからなければ追加提案はしない。見栄えだけの提案や、根拠のない売上向上保証を避ける。
4. **効果を具体化する。** 現状の問題、改善内容、顧客にとって期待できる実務上の変化を短く整理する。効果が推測なら「期待できる」「確認が必要」と表現し、保証しない。
5. **追加費用と納期を提示する。** 作業範囲、成果物、前提、除外事項、追加料金、納期、確認事項を提示する。工数と採算を確認し、既存契約の価格・納期を無断で変更しない。見積に必要な情報が足りなければ、価格を断定せず確認質問を出す。
6. **顧客の判断を待つ。** 希望しない場合も問題なく検収・納品できるよう、契約内の完了状態を明示する。追加作業の承認前に実装・変更をしない。
7. **関係を次の相談につなげる。** 追加提案を断られた場合も、感謝を伝え、今回の契約範囲を予定どおり完了する。必要なら「今後、同様の表示調整や運用改善が必要になった際はご相談ください」と簡潔に添える。繰り返し営業、圧力、プラットフォーム外への誘導はしない。
8. **結果を記録する。** 提案の有無、顧客の回答、承認有無、追加契約額、追加作業時間、次回相談の約束をEvidence付きで記録する。提案を送った事実と受注した事実を区別する。

## 提案文の型

> 納品前に確認したところ、[確認できた現状・課題]がありました。[具体的な改善]を行うと、[顧客が得る実務上の効果]が期待できます。こちらは今回のご依頼範囲外のため、追加[金額]円・[納期]で対応できます。必要でしたら、作業範囲を確認のうえ、プラットフォーム上で正式にお見積もりします。今回は見送る場合も、現在のご依頼範囲で予定どおり納品します。

## 判断と停止条件

- 課題を直接確認できない、効果を説明できない、価格根拠を出せない場合は提案せず、必要なら質問する。
- 既存Scope内の不具合・未達は追加請求せず、契約に従って修正する。
- 追加提案の承認・契約変更がない場合は追加作業を開始しない。
- 発注者の回答がない場合は、契約上の納品を遅らせず、プラットフォームの手順に従う。
- 不採用・辞退後は、相手の意思を尊重して会話を閉じる。将来の相談可能性を残す文面は一度だけとし、追撃しない。
- 追加提案は売上を保証する手法として扱わない。提案数、承認数、追加売上、追加工数、次回相談を計測し、採算と顧客反応を検証する。

## 記録項目

- lead_id / application_id
- scope_check_evidence
- customer_problem_evidence
- improvement_proposal
- expected_customer_effect
- additional_price / estimate_basis
- additional_delivery_time
- customer_decision / decision_evidence
- additional_contract_revenue
- additional_actual_minutes
- next_consultation_signal
